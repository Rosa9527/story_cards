# 剧情抽卡（Story Cards）

给 SillyTavern / TauriTavern 用的手动剧情抽卡插件：**选好卡组 → 点一下「剧情抽卡」→ 从卡库里随机抽一张 → 填进输入框并立刻发送。**

和万华镜（Kaleidoscope）的剧情触发同款做法：卡面内容走**系统导演注注入**，聊天记录里只留下一条极短的触发短语，上下文零负担。

---

## 一、它做什么

1. 面板里按 **分类 → 卡组 → 主题** 三层勾选抽卡范围（与 `cards/` 目录一一对应，可任意组合，父级勾选即整片勾上）；
2. 点「剧情抽卡」，从范围内随机抽一张没抽过的卡；
3. 把卡面 + 注意事项拼成 `<Story_Card_Draw>` 强制指令块，注入到提示词里；
4. 输入框填上 `【剧情抽卡】` 并**立刻发送**，让宿主正常走「玩家发送 → 生成」的链路；
5. 抽到的卡记进当前聊天的「已抽」清单，同一个聊天不会重复抽（可在面板里关掉）。

卡牌正文**不会**出现在聊天记录里，也不会作为玩家发言发给模型——只有一句触发短语。

## 二、装到哪里

插件目录就在卡库旁边，结构如下：

```

├── cards/                 # 卡库：<分类>/<卡组>/<主题>/<卡号>-<卡名>.md

│   └── 现实类/红楼梦/市井生计/C1-03-半盏灯.md
├── js/                    # 源码（普通脚本，共享全局作用域）
│   ├── constants.js       # 常量：DOM ID / 默认设置 / 注入参数 / 超时
│   ├── utils.js           # 设置读写 / 提示 / DOM 小助手
│   ├── host.js            # 宿主适配：getContext / 事件订阅 / 注入 API
│   ├── cards-data.js      # 卡库数据（构建产物，勿手改）
│   ├── cards.js           # 范围树 / 筛选 / 抽卡 / 抽过不重复 / 导入卡合并
│   ├── card-io.js         # 导入 / 导出卡片：JSON 读写 → 入库 / 下载
│   ├── inject.js          # 拼注入块 + 写入宿主槽位 + retry 重放

│   └── main.js            # 入口：bootstrap / 菜单注册 / 事件订阅
├── tools/
│   ├── card-parse.js      # 卡面解析器（构建期用，把 cards/ 下的 .md 解析成卡库数据）
```

宿主只认 `manifest.json` 里的 `js` / `css`，所以 `index.js` 是**构建产物**，改代码请改 `js/` 下的源文件再重新构建。

## 三、构建（加了新卡牌之后必做）

卡牌是**构建期**编进 `index.js` 的（运行时读不到扩展目录里的 `.md`）。所以每加一批卡，都要重新构建：

```powershell
# Windows 一键构建（推荐）
powershell -ExecutionPolicy Bypass -File build.ps1

# 或者直接用 node
node build.js
```

`build.ps1` 会调 `node build.js --stdout` 拿产物、再由 PowerShell 落盘。它比直接 `node build.js` 多一层保险：某些环境（带文件沙箱的宿主、被安全软件托管的进程）会拦住 node 自己的写盘，这时只有 shell 能写。

其他用法：

```powershell
node build.js --cards   # 只重新扫描卡库，生成 js/cards-data.js
node build.js --check   # 校验 index.js 与源码是否一致（提交前跑）
node build.js --watch   # 监听 js/ 与 cards/，改动即重建
```

> **注意**：`build.ps1` 含中文，必须存成 **UTF-8 with BOM**，否则 Windows PowerShell 5.1 会按 ANSI 读、直接语法报错。如果被编辑器改坏了，跑一次 `powershell -ExecutionPolicy Bypass -File tools\fix-bom.ps1` 修回来。

构建完在酒馆里**重载扩展**或刷新页面即可生效。

## 四、加新卡牌

有两条路：

### 路线 A：面板里「导入卡片」（不用构建、立刻生效）

面板顶部有 **导入卡片** 按钮，点它选一个卡牌 `.json` 文件，插件会当场解析并并入卡库：

- 认几种写法：带 `format` / `version` 的导出文件、裸数组 `[...]`、`{ "cards": [...] }`，以及旧版的 `{ "customCards": [...] }`；
- 每张卡需要 `id`（或至少卡号 / 卡名）与 `deck` / `category` / `chapter`；缺层级时归到「未分组 / 未分类 / 未分主题」；
- 同 id 覆盖：自己改过卡面再导入一次即可即时生效；
- 与内置卡完全相同的条目不会重复写入（导出再导入同一份卡库不会让设置膨胀）；
- 导入的卡牌存在酒馆设置里（`extension_settings.storyCards.customCards`），**重启后仍在**；
- 单个文件上限 16 MB，非法 JSON 会被拒绝且不改动现有卡库。

**导出卡片** 把当前卡库（内置 + 已导入）导出成 `story-cards-YYYYMMDD-HHmmss.json`，换设备、备份、手工改卡都靠它。

导出文件长这样：

```json
{
  "format": "story-cards",
  "version": 1,
  "exportedAt": "2026-10-20T07:30:45.000Z",
  "count": 1,
  "cards": [
    {
      "id": "C1-03-半盏灯",
      "number": "C1-03",
      "name": "半盏灯",
      "type": "失去 / 疏忽",
      "deck": "红楼梦",
      "category": "现实类",
      "chapter": "市井生计",
      "face": "……",
      "notes": "……",
      "noteItems": [{ "key": "合理化", "value": "……" }]
    }
  ]
}
```

### 路线 B：放进 `cards/` 再构建（推荐，长期维护）

放进 `cards/<分类>/<卡组>/<主题>/`，文件名建议 `<卡号>-<卡名>.md`（卡号在卡库内唯一），然后重新构建（见上一节）。卡牌编进 `index.js`，不占设置体积，也不怕清设置。

Markdown 结构：

```markdown
# C1-03 半盏灯

**类型**：失去 / 疏忽
**分类**：现实类

## 卡面

（注入给主模型的场景内容……）

## 注意事项

**合理化**：……
**甲是谁**：……

## 设计底稿

（可选，只给作者看，不会进提示词）
```

解析规则（见 `tools/card-parse.js`，构建期使用）：

- **卡面** = `## 卡面` 段正文，是注入的场景内容；
- **注意事项** = `## 注意事项` 段整体，逐条列成落地调整规则一起注入（卡面里的「甲」「那两个人」得靠它落地）；
- **设计底稿** 及任何其它段落一律**丢弃**；
- 段落缺失时降级为空串，不会因为一张卡格式不标准就让整次构建失败；
- 卡片 ID 取文件名主干（如 `C1-03-半盏灯`），因为卡面标题里的卡号写法不统一（`C1-03` / `F16-01` 混用）。

两条路线的卡库是合并的：**内置（构建期）+ 导入（面板）**，同 id 时以导入的为准。新增卡组 / 分类 / 主题不用改任何代码，面板会自动多出对应的勾选项。

## 五、面板怎么用

从 **扩展菜单 → 剧情抽卡** 打开（也可以点屏幕右下角的悬浮按钮）。

- **导入卡片 / 导出卡片**：见上一节。状态行显示当前卡库构成（如「卡库 139 张（内置 138 + 导入 1）」）。
- **抽卡范围**：三层勾选，与 `cards/<分类>/<卡组>/<主题>/` 目录一一对应，**默认全部收起**：先点分类那一行（或行首箭头）展开出卡组，再点卡组那一行展开出主题。
  - 分类 / 卡组的勾选框是三态的（全选 ✓ / 部分 – / 未选 空）：点一下全选整片，再点一下全部取消。
  - 每行的计数一律是 **`已选张数/总张数`**（如 `0张/138张`、`131张/138张`），概况行同理。
  - 一个都不勾 = 全库随机（面板会标注「全库随机」）。
  - 勾了主题 = 只在这些主题里抽。
- **抽过不重复**：默认开。同一个聊天里不重复抽同一张卡；范围内抽完了会明确提示，并允许重复（不会空手而归）。
- **重置记录**：清空当前聊天的「已抽」清单，重新开局用。
- **剧情抽卡**：抽一张 → 注入 → 填输入框 → 立刻发送。结果区显示抽到的卡号卡名与所在分类 / 主题。
- **悬浮球**：右下角的圆球（38px），**按住可以拖到任意位置**，位置存在设置里（重启后还在原处）；拖动会被夹在视口内，横竖屏切换后也不会跑出去。轻点一下打开面板，拖完的那一下不会误触面板。
  - **长按 650ms 隐藏**：按住不动（移动不超过 8px）约 0.65 秒，悬浮球会缩一下收起。长按期间球会轻微放大，提示手势已被识别。
  - 收起后从「扩展菜单 → 剧情抽卡」打开面板，勾上 **显示悬浮球** 就能找回来；面板里也可以直接取消勾选来隐藏。

「已抽」记录按**聊天**分开存在 `chatMetadata` 里，换聊天互不影响。

> **实现说明（勾选框为什么是自绘的）**：范围树的勾选框**不用** `<input type="checkbox">`，
> 而是 `<button role="checkbox">` + `aria-checked`，状态完全由「重渲染后的设置」决定。
> 原因是原生勾选框的点击牵涉浏览器自己的激活时序（翻转 `checked` → `click` → `change`，
> 而 `click` 上 `preventDefault` 又会连带抑制 `change`），这套时序在不同 webview 里并不
> 一致，实测出现过「点了没反应」。自绘按钮没有任何原生状态，点击 → 直接算目标状态 →
> 改设置 → 重渲染，没有时序假设。三态用 `aria-checked="mixed"` 表达。
>
> **设置容器也踩过同一个坑**：TauriTavern 的 `getContext()` 只提供驼峰 `extensionSettings`，
> 而且**每次调用都返回一个新对象**。插件早期只认下划线 `extension_settings`，落到「兜底存储」
> 时又挂在了这个一次性对象上——写进去的勾选下一次渲染就没了，表现同样是「点了没反应」。
> 现在设置按 `extension_settings` → `extensionSettings` → 全局兜底的顺序找容器，
> 兜底也挂在 `globalThis` 上，保证同一页面内读写的是同一份状态。`tests/smoke.test.js`
> 里有专门的回归用例锁住这一点。

## 六、注入块长什么样

抽到卡后，注入到提示词里的内容（`IN_CHAT`，深度 0，SYSTEM 角色，贴在刚发出的触发短语正下方）：

```
<Story_Card_Draw>
【系统导演注 · 强制指令】本块不是剧情正文，也不是任何角色的台词、旁白或可引用文本；它是玩家刚刚主动「剧情抽卡」抽到的一张剧情卡。以下规则必须逐条执行，不得忽略、不得淡化，不得以任何理由整体弃用。

执行规则：
1. 直接驱动：……
2. 自然衔接：……
3. 落地调整：下面的「注意事项」是这张卡在本世界观里的落地说明……
4. 冲突裁决：……
5. 优先级：……

<card id="C1-03-半盏灯" name="半盏灯" type="失去 / 疏忽" category="现实类">
卡面：
（卡面正文……）

注意事项（落地调整规则）：
- 【合理化】……
- 【甲是谁】……
</card>
</Story_Card_Draw>
```

措辞参考万华镜的 `<Story_Event>` 块，刻意写死「不得整段弃用」这类规则，堵掉主模型以「与设定冲突」为由跳过本块的口子。

生命周期：

- **发送前**写入 → 赶在宿主组装主请求 prompt 之前生效；
- **生成结束 / 停止**后清空（卡面已经随本轮请求发出去了，留着只会污染下一轮）；
- **重新生成（retry）/ swipe** 不发 `messageSent`，会在 `generationStarted` 里同步重放同一张卡（不重新抽卡）。

## 七、发送是怎么做到的

宿主 `getContext()` 没有导出「发送」函数，所以按可靠性从高到低依次尝试，并用「chat 是否变长」确认到底有没有发出去：

1. `ctx.sendTextareaMessage()`（宿主若提供就直接用）；
2. 点 `#send_but`（玩家路径，最贴近真人操作）；
3. 在 `#send_textarea` 里敲回车（SillyTavern 绑定的发送手势）。

全部失败时会把输入框清干净，并在结果区说明「可手动按发送键」，**不会**把触发短语留在输入框里干扰玩家。生成中会直接拒绝抽卡，避免打断当前这轮。

## 九、已知边界

- **`cards/` 里的卡牌只在构建期进入插件**：改 `.md` 后不重新构建，酒馆里看到的还是旧卡面（想立刻生效就改完再「导出卡片」→ 改 JSON →「导入卡片」）。
- **`index.js` 是产物**：直接改 `index.js` 会在下次构建时被覆盖。
- **生成中不能抽卡**：插件会拒绝并提示，等这轮结束。
- **宿主不支持 `setExtensionPrompt` 时不发卡**：此时抽卡会报错并中止（而不是发一条没有任何内容的空触发）。TauriTavern 2.x 与标准 SillyTavern 都支持。
- **群聊「重新生成」**：宿主删完尾部 AI 楼层后以 `type='normal'` 重新生成，无法与正常发送区分，不覆盖（与万华镜同一处已知限制）。
- **导入的卡是设置里的一份副本**：会随设置体积变大；长期维护的卡库建议走 `cards/` + 构建。清空酒馆设置会一并清掉导入的卡牌（先「导出卡片」备份）。
